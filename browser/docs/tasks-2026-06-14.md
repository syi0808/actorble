# Actorble Browser Follow-up Tasks - 2026-06-14

이 문서는 `docs/implementation_tasks.md`와 2026-06-14 현재 `browser/` 패키지 상태를 대조해 남은 후속 작업을 정리한다. T0-T40의 core vertical slice는 대체로 구현되어 있으며 `click`, `moveTo`, `typeInto`, visual runtime, scenario delay/pacing 같은 흐름은 테스트로 보호되어 있다. 다만 public API shell, 일부 선언형 조건, scenario action 범위, smoke 검증에는 아직 명시적인 후속 작업이 남아 있다.

## 현재 검증 상태

관찰 시점 기준 검증 결과:

```txt
pnpm test              -> pass, 23 files / 225 tests
pnpm typecheck         -> pass
pnpm build             -> pass

pnpm example:smoke     -> fail
```

`pnpm example:smoke`는 `scripts/action-playground-smoke.mjs`에서 `#run-current` 클릭 후 `#run-status`가 기대 상태로 바뀌기를 기다리다가 timeout 된다. 예제 UI는 새 task scenario 형태로 바뀌었고, smoke script도 일부 정렬되어 있으나 실제 flow 완료 검증은 아직 안정화되지 않았다.

## 의존성 원칙

- Facade는 public API 위임과 composition root만 담당한다.
- Action Orchestrator는 action lifecycle을 조율하고 DOM/event 직접 작업은 platform adapter와 input engine에 맡긴다.
- Geometry 계산과 interactability 판단은 계속 분리한다.
- Pointer/Gesture 계층은 좌표, 버튼, signal sequence를 담당하고 target 의미 상태는 Interaction State Store와 Orchestrator 경계에서 다룬다.
- Browser 한계는 숨기지 않고 capability/fidelity report 또는 `PLATFORM_UNSUPPORTED`로 드러낸다.
- 예제/smoke 작업은 public API만 사용하고 내부 concrete tracker/orchestrator state에 의존하지 않는다.

## 의존성 맵

```txt
example smoke
  -> example/action-playground
  -> actorble-facade public API

actorble-facade
  -> action-orchestrator
  -> target-resolver
  -> geometry-engine
  -> scenario-runner
  -> diagnostics-trace

action-orchestrator
  -> target-resolver
  -> surface-engine
  -> geometry-engine
  -> interactability-engine
  -> gesture-engine
  -> focus-engine
  -> keyboard-engine
  -> text-input-engine
  -> wait-observation-engine
  -> diagnostics-trace

scenario-runner
  -> action-orchestrator
  -> timeline-engine
  -> diagnostics-trace

wait-observation-engine
  -> target-resolver or narrow target wait port
  -> geometry/interactability where needed
  -> timeline-engine
  -> diagnostics-trace

surface-engine
  -> platform-adapter/dom-adapter
  -> shared coordinate primitives

gesture-engine
  -> pointer-engine
  -> pointer-signals
  -> timeline-engine
```

## 첫 후속 vertical slice

가장 먼저 확인할 slice는 browser smoke 복구다.

```txt
example task scenario
-> createActorble({ visual: true })
-> typeInto(..., { focusStrategy: 'click' })
-> click()
-> waitFor({ kind: 'custom' })
-> visual overlay hit-test check
-> smoke pass
```

이 slice가 통과하면 현재 예제가 실제 browser runtime에서 public API만으로 동작한다는 신호가 된다. 그 다음에는 `focus/type/fill/press` shell 제거가 public API 완성도에 가장 직접적인 영향을 준다.
